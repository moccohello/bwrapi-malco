# HUD 상태 연속성

## 문제

- 랠리선, 자원 채집 일꾼, 쉬는 일꾼 표시가 실행마다 다르게 누락될 수 있다.
- 창 표시와 StarCraft 연결 시점이 바뀌면 증상 빈도가 달라지지만, 창 생명주기가 HUD 내용의 정답을 결정해서는 안 된다.
- 기존 코드는 현재 snapshot에 표시할 내용이 있어야 projection demand를 켰다. 시작 시 snapshot이 없으면 demand를 끄고, 첫 snapshot 뒤 다시 켜면서 불필요한 clear가 발생했다.
- 일시적인 command/viewport 불능도 presenter에서 기존 표시 삭제로 이어질 수 있었다.

## 단기 수정 원칙

- Projection demand는 현재 snapshot 내용이 아니라 사용자 설정으로만 결정한다.
- 같은 세션의 일시적인 incoherent command는 마지막 coherent 내용을 유지한다.
- 공간 상태의 명시적인 세션 종료, 세션 변경, 사용자 기능 해제만 기존 공간 표시를 지운다.
- 일시적인 viewport 불능에는 마지막으로 배치한 공간 표시를 유지한다.

## 이번 수정에서 하지 않는 것

- 전역 `Partial` 상태를 통째로 무시하지 않는다. 현재 BWRAPI 계약은 일꾼, 자원, 업그레이드 영역별 완전성을 제공하지 않으므로 전체를 유지하면 실제 상태 변경까지 놓칠 수 있다.
- 임의 지연시간이나 재시도 횟수로 증상을 가리지 않는다.
- installer, launcher, 창 표시 동작은 되돌리지 않는다.

영역별 완전성 계약과 semantic 부분 병합은 진행 중인 데이터 계층 리팩터링에서 다룬다. 현재 진행 중인 worker/resource mapper의 관찰 누락 보정은 그대로 포함한다. 이번 수정은 시작 순서가 달라도 기존의 유효한 공간 상태가 일시적인 command/viewport 불능으로 삭제되지 않게 하는 범위로 제한한다.
